Deprecation & migration playbook
v2.1
Structured process for handling customer migrations at scale
01
Telemetry pull — identify active users
Run the KQL query in Azure Monitor daily to identify tenants with active Synapse API usage. Export results and cross-reference with migration_status table. Flag any tenant with last_seen < 7 days as high-priority.
tool: Azure Monitor · schedule: daily · owner: PM / Data Eng
02
Urgency segmentation
Use SQL query #2 to segment all remaining tenants into CRITICAL / HIGH / MEDIUM / LOW based on days to EOL and migration completion %. CRITICAL tenants (<14 days) require same-day outreach escalation.
tool: Azure SQL · output: prioritised outreach list
03
Personalised outreach — first contact
Send migration notice referencing actual usage data (API calls, pipeline runs). Attach Fabric migration guide. Include specific EOL date and offer FastTrack engineer assignment. Do not send generic emails — reference tenant-specific telemetry to increase response rate.
channel: email + Azure portal banner · SLA: 48h response target
04
Response tracking & follow-up cadence
Log all customer responses in CRM. For non-responders: Day 3 → follow-up email. Day 7 → escalate to account team. Day 12 → final warning with portal banner. If still no response at D-7 to EOL, trigger mandatory escalation workflow.
tool: CRM + internal ticketing · owner: PM + CSM team
05
Migration validation
After customer confirms migration, verify via telemetry that Synapse API calls have dropped to zero and Fabric API calls have increased proportionally. Update migration_status table. Only close the ticket once both conditions hold for 3 consecutive days.
tool: KQL query #4 · validation period: 3 days
06
Post-migration support window
Keep FastTrack engineer available for 30 days post-migration. Monitor for regressions. Collect feedback to improve playbook. Update documentation based on common blockers encountered.
owner: FastTrack team · duration: 30 days post-migration
